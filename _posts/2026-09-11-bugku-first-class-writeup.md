## 一、题目信息
- **题目名称**：头等舱
- **题目类型**：Web
- **靶场来源**：Bugku CTF

## 二、解题过程

**1. 启动环境，页面无有效信息**
启动靶机后，打开题目页面，页面上没有显示任何有用的内容，也没有明显的输入框或提示信息。
按照常规习惯，按 `F12` 查看网页源码，源码中同样没有发现 flag 或相关提示。

**2. 分析题目名称，寻找突破口**
题目名为「头等舱」，这是一个很明显的提示：
- 「头」对应英文 **Head**，暗示与 **HTTP 头部（Headers）** 有关；
- 部分版本的题目文件名为 `hd.php`，进一步印证了解题方向在 HTTP 头部。

这里需要注意区分：Flag 可能藏在 **请求头（Request Headers）**，也可能藏在 **响应头（Response Headers）**。本题的关键在响应头。

**3. 抓包查看 HTTP 响应头**
使用抓包工具（如 **Burp Suite**）或浏览器开发者工具（`F12`）的 **Network（网络）** 面板：
- 打开 `Network` 面板后刷新页面；
- 点击第一个请求，在右侧找到 **Headers（标头）** 选项卡；
- 向下滚动到 **Response Headers（响应标头）** 区域；
- 在响应头中发现了一个自定义字段，其对应的值就是真正的 Flag。

**4. 提取 Flag**
在响应头中拿到 Flag 字符串。
最终提交的 Flag 是：`flag{这里填入你实际提交的flag内容}`

## 三、总结与心得
这道题是典型的 **HTTP 协议头部信息泄露**。它让我明白了：
1. Flag 不一定藏在页面内容或源码里，也可能藏在负责传输页面的 HTTP 数据包的头部字段中。
2. 解题时要养成抓包的习惯，同时关注 **请求头** 和 **响应头**，不要只看其中一边。
3. 题目名称、文件名往往就是最直接的提示，比如「头等舱」「hd.php」都指向了 Headers 方向。
